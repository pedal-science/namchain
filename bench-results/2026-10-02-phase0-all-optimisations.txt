Why
---
pedal.project docs/multi-core.md develops and tests the multi-core work against this core, so that
the A2 planar kernels and the IR optimisations are both in the tree. The fork's base is exactly the
commit namchain pinned (2563c0f), so the move is additive.

What changed
------------
- .gitmodules: vendor/NeuralAmpModelerCore -> the rikkus fork, branch all-optimisations.
- vendor/patches/0001-a2-planar-neon-kernels.patch removed: the branch contains the planar work (the
  NAM/ portion of that patch reverse-applies cleanly to it). It failed to apply verbatim only
  because tools/CMakeLists.txt moved upstream, and namchain does not build the core's tools.
- CMakeLists.txt: the A2 planar summary gate no longer depends on NAMCHAIN_APPLY_VENDOR_PATCHES; the
  kernels are in the core now, not in a patch. (Leaving it would have reported "OFF" for a build
  that has them, the same class of bug plan.md §9.4 records for armv7.)
- AGENTS.md: records the core branch and which Linear implementation nc.cab.ir gets.

What came along with the branch: upstream after 2563c0f (v0.6.0, #333 variable sample rate, #335
1-to-n/n-to-1 Linear, #337 WAV-instantiated Linear). Linear's constructor is source-compatible (the
new `implementation` parameter defaults to Auto) and the dependency pins are unchanged
(AudioDSPTools 0827c6c, Eigen bc3b398), so no other namchain change was needed.
