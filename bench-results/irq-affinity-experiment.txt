  1. the helper was named `expand`, which collides with /usr/bin/expand, so bash ran the external

     reporting the busy state.
  4. overlapping leftovers from attempts 1-3 then ran as two concurrent instances, competing for the same
     device, so most arms failed while a few produced partial deltas.

`kill -9` on those instances bypassed the script's trap, which is what restores the masks: it left **25 of
the 59 IRQs** steered away from cpu 3. Caught by the same verification the experiment uses on itself, and
restored from the saved originals -- 0 differences across 59 IRQs, no processes left, device free.

What is now known and usable:

  * the design is settled: alternating A/B pairs, because two arms of the *same* configuration 20 minutes
    apart differed by 8.8 points of chain p99, so only within-pair differences are trustworthy;
  * the manipulation is settled and *measured*: 59 steerable IRQs, **56 of them currently deliverable to
    cpu 3**, and arm B removes cpu 3 from all of them (`0-3` -> `0-2`) -- nothing on this machine steers
    away from the audio core today, and `irqbalance` is inactive;
  * the check that the manipulation happened is per-run: cpu 3's interrupt count for that arm's own
    duration. It caught attempt 1 (deltas identical at ~291 400 across all four arms) and it will show
    immediately whether a B arm is really a B arm;
  * the limit that bounds a null result: only *steerable* IRQs move. The arch timer, IPIs and RCU
    callbacks are per-CPU and cannot be steered from /proc -- exactly the sources a
    nohz_full/rcu_nocbs/threadirqs boot configuration addresses. So this tests the device-IRQ half, and a
    null result would not rule out interrupt work from the non-steerable half. That is what the RT kernel
    being prepared would cover.
