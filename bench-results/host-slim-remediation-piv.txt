# host-slim: the manifest defect, and the round trip that proves the fix -- piv
#
# Generated 2026-09-17 on piv from real tool output; the transcripts below are verbatim.
#
# WHAT WAS WRONG
#
# `--apply` truncated the manifest (`: > "$MANIFEST"`) on every run. The mask step records a
# `mask <unit>` line only for units it actually masks, so the second apply found the units
# already masked, recorded nothing, and left a manifest that no longer mentioned any of them.
# `--revert` then had no line to unmask them with, and silently left all 32 in place while
# reporting success for the parts it could see.
#
# It was found because `tools/soak/host-slim-capture.sh` recorded the board state rather than
# only a pass/fail: piv -- believed to be "applied on both boards" -- was in fact half
# reverted. Its cpusets read 0-3 and all five files were absent, but 32 units were still
# masked. The old `--check` called that green because it counted "masked" together with
# merely "not-enabled" and never compared the masks against the manifest.
#
# THE FIX (tools/soak/host-slim.sh)
#
#   1. The manifest is merged, not reset: re-applying keeps the mask lines that say the units
#      are ours. (manifest_add already de-duplicated, so lines do not accumulate.)
#   2. --check now counts services that are masked WITHOUT a manifest line and reports them
#      with a WARN, so this state can never again pass as green.
#   3. --list-services prints the board's mask set, so a reconciliation is auditable rather
#      than a hand-written list.
#   4. Related defect in the same area: init.scope is a *transient* unit (no fragment), so a
#      drop-in under /etc is ignored for it -- verified directly. Its confinement used to
#      decay at every reboot. It is now re-applied by a boot oneshot
#      (namchain-host-slim-initconfine.service) whose ExecStartPost asserts the read-back,
#      and machine.slice (non-transient) now gets a drop-in like the other slices.
#
